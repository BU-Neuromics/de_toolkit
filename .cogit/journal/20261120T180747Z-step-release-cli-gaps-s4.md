DETK-0032 and the acceptance:
- Generated by shtab, no runtime dependency: shtab>=1.13.0 is in the dev group only (uv.lock pins 1.13.0). I built the wheel: its Requires-Dist has no shtab, and it ships de_toolkit/completions/detk.{bash,zsh,tcsh}. In a fresh 3.11 venv with only the wheel (shtab not installed), `detk completion bash|zsh|tcsh` exits 0 and prints files byte-identical to the repo's. `detk completion fish` exits 2 with the usage. The scripts are generated in development and committed, not by a build hook; the acceptance allows that, since a build hook is only one option. _generate.py ships in the wheel but imports shtab only when it runs.
- The regeneration test: test_shipped_script_is_current compares each shipped file with generate(). Re-running `python -m de_toolkit.completions._generate` leaves no diff. test_script_covers_every_command_and_subcommand checks every command (detk and each detk-<command>) and every subcommand for all three shells.
- Bash behaviour: the bash tests drive the shipped script's completion function (every subcommand; `--si` gives `--size-factors` both through detk and detk-norm; `detk completion` offers the three shells; `-f` offers its choices). By hand, after `eval "$(detk completion bash)"` from the installed wheel: detk and every detk-* get a function of their own (separate prefixes, so detk's `de` and detk-de don't collide), a <counts_fn> completes to file names, and -o FILE to paths.
- `detk completion <shell>` has help like the others (description saying how to load each shell, examples, the exit codes epilog), is listed in `detk --help` and its usage, and is pinned in tests/cli (prints the shipped file, rejects a missing shell, an unknown shell, an extra argument and an unknown option, each with exit 2). test_completion_needs_no_shtab runs it with shtab blocked from import.
- The runtime-only check passes. CHANGELOG (Added) and commands.md describe the command.

Not blocking:
- zsh and tcsh are not installed here or in CI, so only their content is tested (coverage and regeneration), not their behaviour. The zsh file holds 11 shtab scripts, one after another; each calls `compdef` when eval'd, so the documented `eval "$(detk completion zsh)"` works. Put on fpath as a single `_detk` file it would complete only detk; the help documents eval only, so this is fine.
- tests/check_runtime_deps.py (outside this node's scope) could also run `detk completion bash` with --no-dev. test_completion_needs_no_shtab and the wheel check above already cover that.
- The regeneration test compares exact shtab output, so a dev with a newer shtab than the lock's will see it fail. The lock pins 1.13.0 and the failure message gives the regenerate command.
